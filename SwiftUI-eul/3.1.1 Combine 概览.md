WWDC 2019 上与声明式框架 SwiftUI 一同发布的，还有同等重要的响应式框架 Combine，它用于处理（异步）事件和数据流。随着 Concurrency 框架的发布和 SwiftUI 的不断完善，可能在实际开发中 Combine 直接露面的概率会越来越小。但它是 SwiftUI 简洁高效的基石，了解它有助于更好地理解和使用 SwiftUI。

Combine 框架包含三个核心概念：Publisher、Subscriber、Operator。

# Publisher（发布者）

Publisher 是一个协议，遵循这个协议的对象，我们称之为发布者，它可以向订阅者（Subscriber）发送数据。

一个发布者可以有多个订阅者，如果没有任何订阅者，那么数据流中不会产生任何数据。

Publisher 定义了两个关联类型：

```swift
// Publisher 发送的数据
associatedtype Output
// 可能会遇到的错误
associatedtype Failure : Error
```

# Subscriber（订阅者）

订阅者可以接收发布者发送的数据，与发布者类似，它也是一个协议，定义了两个关联类型：

```swift
// 从 Publisher 接收到的数据
associatedtype Input
// 可能接收到的错误
associatedtype Failure : Error
```

数据流中会随着时间的推移产生许多的数据，有一点是必须要遵守的：订阅者的 Input、Failure 必须要和发布者的 Output、Failure 保持类型一致。

# Operator（操作者）

我们可以把数据流想象成一条生产线，Publisher 位于上游，Subscriber 位于下游，而 Operator 则位于中游，它可以对数据流中产生的数据进行加工。Operator 不是必须存在的，只有我们需要它时才会调用。

打个比方，Publisher 是牧场，发送一头头生猛的牛，中间有一系列的 Operators，有的 Operator 负责屠宰、有的负责运送、有的负责烹饪等等，最终到达 Subscriber 的是一块香喷喷的牛排！我们只需要享受美味即可，其它的工序交给中间的操作者去处理即可。当然，我们也可能收到一些意外情况，比如某个中间环节出了问题，最后我们收到的不是牛排，而是 Failure。

以上就是 Combine 中最为关键的三个核心内容的概念性介绍，后续的主要内容都会围绕这三个概念展开。
