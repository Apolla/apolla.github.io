SwiftUI 的布局过程大致如下：

1. 父视图为子视图提供布局空间。

   - 若指定了尺寸，父视图提供的布局空间就是指定的尺寸范围。
   - 若没指定尺寸：
     - 若父视图是无边界的，比如 Color 还有下面提到的 ScrollView，它的尺寸默认是无限大（这里的无限大指可以利用的一切空间，下同）。
     - 若父视图是有边界的，比如 HStack、VStack 等，它的尺寸取决于子视图的尺寸。

2. 子视图根据自身内容计算尺寸，并将该信息提供给父视图。

   SwiftUI 中的视图层级类似树状结构，对每个节点视图的 body 属性的计算是个递归的过程，终止条件是遇到 body 属性为 Never 的视图，它们又称为原始视图，是这颗树上的叶子结点。这里提到的父子关系并非绝对概念，子视图可能也作为其它视图的父视图，父子其实是个相对概念。

3. 父视图根据子视图提供的尺寸信息计算自身尺寸并对子视图进行布局。

   - 若父视图指定了尺寸，则根据指定的尺寸对子视图进行布局。
   - 若父视图没指定尺寸，则根据子视图提供的尺寸信息计算自身的尺寸并对子视图进行布局。父视图在计算自身尺寸时如果它本身就是无边界的，那么它的尺寸不受子视图的影响。

SwiftUI 中大部分视图都是有边界的，比如 Text、Button、VStack 等，它们的尺寸是自适应于内容的，即使周围有可以利用的空间，它们只占用自身尺寸所需要的空间。而有些视图是无边界的，只要不指定尺寸去约束，它们就会贪婪地占用一切可以利用的空间。

接下来通过示例来加深对 SwiftUI 布局过程的理解，首先添加一个 ScrollView，并添加一个蓝色背景：

```swift
struct SampleLayoutSystem: View {
  
  var body: some View {
    ScrollView(.vertical) {
			
    }
    .background(.blue)
  }
}
```

由于 ScrollView 是无边界的，它没有指定尺寸，也没有子视图提供尺寸信息给它，因此它的尺寸是无限大的。前文提到过，Color 本身也是 view，而且是无边界的。这里的蓝色背景实际上是在 ScrollView 的下面一层添加了一个蓝色的 view，它的尺寸取决于 ScrollView 的尺寸，而 ScrollView 是无限大的，所以我们看到蓝色铺满了 SampleLayoutSystem 整个视图。

如果将 ScrollView 换成 HStack、VStack 等有边界视图，是无法看见蓝色背景的。因为它们本身不具备 ScrollView 的贪婪特性，又没有子视图将其“撑大”，所以自身没有尺寸，无法看见蓝色。

然后给 ScrollView 添加一个子视图：

```diff
// 默认滑动方向是 .vertical
ScrollView(axis) {
+   Text("Hello World")
+     .background(.orange)
}
```

Text 根据文本内容计算出自身的尺寸后将其告知 ScrollView，ScrollView 获取该信息后计算出自身宽度后重新布局，最终可见的蓝色背景的宽度和 Text 的文本内容宽度是一致的。

这里需要说明一下 ScrollView 的特殊性，它是一个可以滑动的视图，在指定可滑动的轴向上是无边界的，在未指定滑动轴向上是有边界的。

这里我们没有指定滑动轴向，初始化时默认是 `.vertical` ，所以在添加 Text 之后，ScrollView 在垂直方向上的高度是无限大的，在水平方向上的宽度是根据 Text 所需空间计算出来的。

如果将代码做如下修改，那么蓝色区域高度和 Text 一致，宽度是无限大。

```diff
- ScrollView {
+ ScrollView(.horizontal) {
```

如果将代码做如下修改，那么 ScrollView 的尺寸不再受 Text 的约束，蓝色区域会铺满整个视图。

```diff
- ScrollView {
+ ScrollView([.horizontal, .vertical]) {
```

前文也曾提到，修饰器方法的顺序会影响到视图的外观，比如下面的两套代码呈现的结果是不一样的。

```swift
// 1
Text("Hello World")
  .frame(width: 200, height: 100)
  .background(.orange)
  .padding()
  .background(.purple)

// 2
Text("Hello World")
  .background(.orange)
  .frame(width: 200, height: 100)
  .padding()
  .background(.purple)
```

原因之前也提到过，SwiftUI 中的 frame 有别于 UIKit，它不是视图的属性，而是一个返回 `some View` 的修饰器方法，它的作用是向父视图提供尺寸信息作布局之用。

比如下面的代码，父视图从子视图中获取到的尺寸信息如下：

- 橙色区域的尺寸是 200 * 100。
- 文本是左上角对齐。

```swift
Text("Hello")
  .background(.blue)
  .frame(width: 200, height: 100, alignment: .topLeading)
  .background(.orange)
```

于是父视图给子视图分配 200 * 100 的空间，然后将 Text 置于橙色区域的左上角。

又比如下面的代码，VStack 中的子视图的尺寸由自身决定，它们向父视图传递的尺寸信息也决定了 VStack 的尺寸，VStack 能够通过改变 alignment 来决定它们的对齐方式。

```swift
VStack(alignment: .leading) {
  Text("Hello")
    .background(.blue)
    .frame(width: 200, height: 100, alignment: .topLeading)
    .background(.orange)
  
  Text("World")
    .frame(width: 100, height: 100)
    .background(.orange)
}
.background(.purple)
```

SwiftUI 的布局系统稍微有点复杂，视图的布局是由父视图和子视图协同完成的。以上仅为抛砖引玉，深入理解需要更多的实践和总结。
